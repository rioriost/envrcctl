# 0.4.0 candidate validation — 2026-09-16

## Status

The signed candidate is prepared and validated. **Publication is pending
notarization.** An existing `notarytool` Keychain profile name must be supplied
before the exact signed helper can be submitted to Apple. Do not publish the
helper as a notarized release or rebuild/re-sign these candidate bytes afterward.

## Completed checks

- Both `.zed/scripts/verify` and `.zed/scripts/verify-release` passed. The normal
  verification script used the project Python and actually ran pytest/Bandit.
- Full suite: **716 passed, no skips**. Application coverage: **97.21%**,
  exceeding the configured 95% release threshold.
- Ruff passed across `src`, `tests`, and `scripts`.
- Bandit passed using the repository's existing exclusions. Fixed diagnostic
  strings have narrowly documented B105 suppressions; they are not credentials.
- Actual Bash 3.2, Zsh, and Fish completion tests passed for commands, options,
  and paths. Fish was installed after the missing-shell prerequisite was detected.
- Regression coverage includes literal/Unicode/CRLF round trips, PTY shell
  capture and failure propagation, transactional reference rollback, canonical
  aliases, concurrent audit updates, schema-1 compatibility, correlated exec
  lifecycle, malformed inputs, native protocol fidelity, and packaging failures.
- The Python wheel was installed into a fresh temporary environment constrained
  by `uv.lock`. The installed version, CLI help, init/set/get/unset, exact shell
  values, and read-only verification of an empty audit store passed.
- Wheel and source archive membership checks exclude the generated native helper
  and its backups.
- The production helper was rebuilt with SDK 27.0 for arm64/macOS 26.0, signed
  with the existing Developer ID Application identity, and passed
  `codesign --verify --strict`. Its `--help` runs without authentication.
- The checked-in helper was replaced with the exact bytes from the signed helper
  archive, not independently recompiled or re-signed.
- Formula Ruby syntax and helper deployment metadata checks passed.
  Provenance-validated `--formula-only` succeeded after replacing the helper.

The Swift compiler reports the existing `SecKeychainCopyDefault` deprecation.
The traditional Keychain path is retained for compatibility; switching stores
would change the identity/location of existing items.

## Validation boundaries

No real user secret was read, written, deleted, copied to a clipboard, or passed
to a child during testing. Native authentication tests use synthetic protocols;
Touch ID/Apple Watch prompts, existing Keychain ACL interoperability, and a live
Linux SecretService session were not exercised. Signing used the operator's
existing signing identity. No notarization, GitHub release, or PyPI upload has
been performed for this candidate.
