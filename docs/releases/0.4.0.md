# envrcctl 0.4.0 — reliable secret and file lifecycles

This release addresses the design/code review of 0.3.2. It corrects shell value
round trips, guarded direnv capture, filesystem updates, backend protocols,
audit durability, and release packaging.

## Upgrade notes

- `secret unset VAR` now removes only the local reference. Deleting the shared
  OS-store item requires `--delete` and confirmation (`--yes` for automation).
  Check other projects before deleting an item. Local aliases, including legacy
  references and different kinds, are recognized by backend identity.
- Run `envrcctl init --inject --yes`, inspect the updated `.envrc`, then run
  `direnv allow`. The generated fragment uses checked `inject --shell` capture;
  it requires a controlling terminal and retains mandatory macOS owner
  authentication. Unattended Linux use still requires explicit `--force`.
- Secret input and backend output now preserve whitespace and line endings.
  Use `printf %s "$TOKEN"` for stdin rather than newline-appending `echo`.
  Previous SecretService writes may have stored an extra newline. Review and
  explicitly re-register affected entries; the upgrade does not guess which
  newlines were intentional.
- macOS requires Apple Silicon, macOS 26+, and the matching native helper.
  Keychain writes now use the helper's stdin-fed Security-framework operation,
  never a plaintext password in process arguments. SecretService on macOS is
  rejected rather than bypassing the authentication policy.
- `migrate` refuses dynamic shell code, conditional assignments, and conflicting
  definitions without changing the original file. Resolve these cases manually.

## Audit compatibility

New schema-2 records extend existing schema-1 hash chains without rewriting old
records. `exec` writes a durable `started` event before child startup and a result
with the same `operation_id`. A start without a result means completion is unknown.
Arguments and raw external error strings are not recorded in new events.
Old records may still contain command arguments.

Audit writers are serialized, and verification is read-only. Insecure permissions,
corrupt records, and inconsistent sidecars fail closed instead of being silently
repaired. Preserve the store when diagnosing a failure; do not delete history
to suppress it. Local hashes do not protect against rewriting all history and
sidecars or deleting the entire store.

## Implementation and distribution

Managed values round-trip quotes, multiline text, and Unicode without executing
shell expressions. Writes use exclusive temporary files, preserve permissions,
and detect conflicting updates. Secret changes prepare file updates before
changing the OS store and restore references if the backend operation fails.

The release pipeline propagates failures, orders parallel Make stages, avoids
renaming the working helper, and checks artifact provenance. Completion scripts
use Typer's protocol, the formula declares the helper's minimum macOS version,
and verification supports the stock macOS Bash.

Production builds now resolve the nonsecret Keychain profile name from explicit
options, environment variables, or persistent project settings and validate it
with `notarytool` before any build. `make release-check` requires matching
provenance and an Apple `Accepted` receipt tied to the actual artifacts.
Unnotarized development output requires explicit `--candidate` and cannot pass
the publication gate; missing profile selection is not reported as missing
stored credentials.
